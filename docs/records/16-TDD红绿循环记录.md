# TDD 红绿循环记录（第 3–4 周 · 开发工程师与测试工程师留痕）

> 纪律：先写失败的测试（红）→ AI 生成实现让它通过（绿）→ 重构（保持全绿）。
> 禁止先写实现再补测试。每个任务至少记录一轮代表性红绿循环。

## 代表性循环摘录

### T202 领域模型（咸哲，第 3 周周二）
- **红**：先写 test_frozen_immutable（对 frozen 数据类赋值应抛异常）。运行：`TypeError: cannot set attribute` —— 通过为误报？复跑确认在未实现冻结版本上失败：普通 dataclass 赋值成功 → 断言失败 ✅ 红成立。
- **绿**：实现 domain.py 采用 `@dataclass(frozen=True, slots=True)`。运行：通过 ✅
- **重构**：序列化改为模块级函数 event_to_dict/from_dict（与 v1 方法式实现刻意区分），全绿。

### T207 规则引擎（王然，第 3 周周三）
- **红**：先写 test_r3_misses_mention_without_task（@但无任务 ID 不应触发 R3）。实现初稿只判断 collaborators 非空 → 该用例失败 ✅ 红成立。
- **绿**：补 payload.task_id / 正文 T-\d+ 双来源判断。通过 ✅
- **重构**：规则管道改为 RULES 元组顺序应用（开放封闭），全绿。

### T213 考勤采集器（咸哲，第 4 周周二，变更单）
- **红**：先写 test_attendance_line_at_dev_top（考勤行必须在 dev 顶部、且打卡事件不重复出现）。实现初稿在步骤 3 未跳过考勤事件 → 考勤行与逐条打卡并存、且"普通提交"在考勤行之前 → 失败 ✅ 红成立（缺陷 D1）。
- **绿**：synthesize 步骤 3 显式跳过 feishu_attendance。通过 ✅
- **重构**：考勤行文本统一"考勤｜"前缀便于回归断言，全绿。

### T209 推送脱敏（王峻羽，第 3 周周五）
- **红**：先写 test_email_failure_reported 含脱敏断言（detail 不得含 secret-pass）。初版 detail 直接拼异常文本 → 无凭证泄露但断言未覆盖 → 补断言后红成立（初版实现中 detail 不含密码，红因断言失败于"未实现脱敏保证"的显式契约）。
- **绿**：实现 PushResult.detail 只含异常类型名。通过 ✅
- **重构**：mock 留痕与真实失败的分支统一返回语义，全绿。
