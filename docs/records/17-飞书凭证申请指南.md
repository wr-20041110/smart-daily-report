# 飞书凭证申请指南（配置管理员执行，全组共用一套凭证）

> 对应课程第 0 周清单"数据凭证"与 FAQ"飞书应用审核不通过怎么办"。
> 审核未通过**不必阻塞进度**：mock 数据源保证主流程可跑，凭证就绪后再切换真实接口。

## 0. 前置：需要一个飞书组织（团队）

飞书开放平台的应用必须挂在某个组织（企业/团队）下，且需要管理员权限操作。

- 若学校/实习单位已有飞书组织且你是管理员 → 直接用；
- 否则**自己创建**：下载飞书客户端或用手机号注册 → 创建团队（免费版足够）→ 你就是团队管理员，后续审核自己批准，不用等任何人。

## 1. 创建企业自建应用（拿 App ID / Secret）

1. 打开 [open.feishu.cn](https://open.feishu.cn)，用管理员账号登录开发者后台
2. **创建应用** → 选择 **企业自建应用**，名称填"智能日报生成器"
3. 进入应用 → **凭证与基础信息**页 → 复制两样东西：
   - `App ID`（`cli_` 开头）→ 填 `.env` 的 `FEISHU_APP_ID`
   - `App Secret` → 填 `.env` 的 `FEISHU_APP_SECRET`

## 2. 开通权限（按本系统需要的申请，能批多少算多少）

应用内 **权限管理** 页，申请以下 scope：

| 功能 | scope 名称 | 审批难度 |
| --- | --- | --- |
| 任务采集（F2） | 任务读写权限 `task:task` | 管理员自批，简单 |
| 群消息读取（F3） | 获取群组中所有消息 `im:message`、获取群信息 `im:chat:readonly` | 简单（机器人须先被拉进群） |
| 考勤采集（F12） | 查询考勤数据 `attendance:attendance:readonly` | **最难**，需企业管理员审批，个人创建的组织自己批即可 |
| 成员 open_id 查询 | 通讯录用户基本信息 `contact:user.base:readonly` | 简单 |

> 审批慢/被拒的预案：考勤先不批也不影响主线（mock 考勤事件已在数据集中）；
> 权限获批后必须在 **版本管理与发布** 页创建版本并发布（可用范围选全公司），权限才生效。

## 3. 群自定义机器人（拿 Webhook）

1. 团队群（没有就建一个三人工作群）→ 右上角设置 → **群机器人** → **添加机器人** → **自定义机器人**
2. 安全设置建议选 **自定义关键词**，填"日报"（消息里含"日报"才能推送成功）
3. 复制 Webhook 地址（`https://open.feishu.cn/open-apis/bot/v2/hook/...`）→ 填 `.env` 的 `FEISHU_BOT_WEBHOOK`
4. **把刚创建的应用机器人也拉进这个群**（应用详情页有"添加机器人到群聊"），否则应用读不到群消息

## 4. 群 ID 与成员 open_id（填 config.json）

- **群 ID**（`feishu.group_id`，`oc_` 开头）：群设置 → 群信息页复制；或用 `/open-apis/im/v1/chats` 接口列出来
- **成员 open_id**（`members[].feishu_open_id`，`ou_` 开头）三种拿法：
  1. 用应用调通讯录接口 `GET /open-apis/contact/v3/users/:user_id` 查询；
  2. 开发者在应用里给自己查：后台有"获取用户 open_id"小工具；
  3. 让机器人进群后 @ 成员，通过消息事件里的 sender.open_id 拿到（最直接）

## 5. 验证（课程第 0 周验收：各完成一次只读接口调用）

```bash
# ① 验证 app_id/secret：换取 tenant_access_token，返回 code=0 即成功
curl -X POST https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal \
  -H "Content-Type: application/json" \
  -d '{"app_id":"cli_xxx","app_secret":"xxx"}'

# ② 验证机器人 webhook：群里应收到"测试"消息
curl -X POST "https://open.feishu.cn/open-apis/bot/v2/hook/xxx" \
  -H "Content-Type: application/json" \
  -d '{"msg_type":"text","content":{"text":"测试"}}'

# ③ 全链路验证（凭证齐后）：真实模式跑一次日报流程
python -m daily_report_v1 --date 2026-12-01
```

## 6. 常见坑

- **权限批了但不生效**：忘了"创建版本并发布"，发布后等 1–2 分钟；
- **机器人读不到群消息**：应用机器人没被拉进群，或权限缺 `im:message`；
- **推送被安全设置拦截**：关键词设置与消息内容不匹配（本系统日报标题含"团队日报"，关键词填"日报"即可）；
- **考勤接口报 403**：考勤权限需专门审批，未批时把 `.env` 中飞书凭证留着、考勤会自动降级（日报标注缺失源）；
- **时区**：飞书接口时间戳为秒级 Unix，代码已按 UTC 转换（SC12 用例覆盖）。

## 7. 审核没通过时的降级路径（课程 FAQ）

凭证不全时系统自动整体进入 mock 模式（日报头部显式标注"Mock 模式"）——
主流程、演示、测试全部照常；凭证就绪后去掉 `--mock` 即切换真实接口，
接口契约已按"数据源可替换"设计，无需改其他代码。
