# 双轨建模对比（第 2 周任务 3 · 300 字 · 架构师：咸哲）

UML 图与 Markdown 规范各自适合表达什么、在本项目中如何配合：

UML 图擅长表达**结构与关系**：用例图一眼看清参与者和功能边界，类图固定模块间的依赖方向，ER 图把实体关系画成可讨论的拓扑。它的优势是空间化、整体性，人脑处理关系时比读文字快得多；劣势是细节承载弱，字段约束、行为语义塞不进图里，且改动成本高。Markdown 规范擅长表达**契约与理由**：接口的入参出参、错误码、行为约束可以写成逐条可验证的文字，ADR 把"为什么这么选"讲透。它的劣势是关系淹没在段落里，读文字重建结构慢。

本项目两者配合的分工是：**图定骨架，文定契约**。design.md 正文写模块职责、接口契约、ADR 与验收语义，UML 附件画四层架构的用例图、类图、ER 图与泳道图——图是正文的"索引与快照"，正文是图的"细节与理由"。评审时先看图查结构错误（漏模块、错依赖），再读文查契约错误（漏边界、不统一）。单一表达都会失明：只有 Markdown 时红队评审漏掉了"考勤源未进架构图"这类结构问题，只有 UML 时契约的可测性无处安放。双轨并用，图的每一次改动都必须同步正文——这也是第 4 周"规范守护"检查的核心对象。
