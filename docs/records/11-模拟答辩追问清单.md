# 模拟答辩追问清单（第 4 周 · 组内轮流扮演专家互相追问）

> 方法：整理"评审专家追问清单"，按架构决策、安全、异常处理、并发四类组织；
> 组内模拟答辩中每问必答，答不上来的问题记入项目总结报告第 6 章（不足与改进）。

## 架构决策类

1. 为什么选 httpx 而不是 requests？——ADR-001：连接池与超时原语直接满足 ≤20 请求约束；requests 重试语义依赖 urllib3 内部参数。
2. 为什么 SQLite 而不是 MySQL？——ADR-002：单团队数据规模远低于 SQLite 上限；UNIQUE 约束天然支持去重与幂等；零部署。
3. v1 和 v2 架构差异是什么、为什么第二阶段要重做？——v1 继承式分层类架构，v2 注册表+规则管道纯函数架构；重做是课程对比要求，v2 新增数据源只注册不改核心，开放封闭性更强。
4. 协同归属 R3 为什么要求"关联任务"才算协作，@了就算不行吗？——纯寒暄式 @ 会造成归属噪音，错挂比漏挂更糟（H4）；任务 ID 是可解释的强信号。

## 安全类

5. 凭证怎么管理？——仅环境变量注入，config.json 只放非敏感配置（ADR-003）；.gitignore 排除 .env 与 data/；日志脱敏。
6. SQL 注入怎么防？——存储层全参数化占位符，无字符串拼接。
7. 邮件授权码会不会出现在推送日志里？——不会：PushResult.detail 只含错误类型与收件人数，测试有脱敏断言。

## 异常处理类

8. 飞书接口 500 了怎么办？——重试 3 次指数退避（1s/2s/4s）后降级出报，缺失源在日报显式标注（ADR-004）。
9. 重跑同一日期会重复出数据吗？——不会：raw_events 有 (source, ref) UNIQUE 约束 + INSERT OR IGNORE，日报表 INSERT OR REPLACE，测试覆盖幂等重跑。
10. 生成层崩溃会不会把半成品日报推出去？——不会：存储/生成失败抛异常、CLI 退出码 1，推送在存储之后才执行（design 4.5）。

## 并发类

11. 多个采集器同时写 SQLite 会冲突吗？——v1/v2 均为串行采集、单连接写入；SQLite 单写者模型下无并发写场景。若未来引入并行采集（executing-plans 子智能体），需改造为采集并行、写库串行。
12. 邮件和飞书推送并行还是串行？——串行，任一通道失败不阻断另一通道（PushResult 各自独立）。
