# 技能拆解笔记（第 2 周前导练习 · 全员各写一段，此处为王然笔记示例）

> 任务（指导书 5.1.3）：任选一个 Superpowers 技能包，对照 SKILL.md 关键要点（触发描述、
> 正文简短、细节放 references/ 与 scripts/）完成一次"拆解阅读"，为第 3 周调用工作流做准备。

## 拆解对象：Superpowers 技能库 brainstorming（头脑风暴）技能包

**它的触发描述写了什么？**
frontmatter 的 description 明确写清"何时加载"：当需求模糊、需要澄清问题而非直接给方案时触发；
并写明输入（模糊需求描述）与输出（一问一答式需求记录）。对照指导书 5.1.1①，这正是"触发时机 +
适用场景 + 处理对象"的标准写法——所以第 3 周我发起头脑风暴时，它会被稳定触发。

**正文如何保持简短？**
SKILL.md 正文只有指令式步骤（先逐条提问、再沉淀为需求记录），没有把提问清单本身塞进正文；
完整的问题清单模板放在 references/ 里按需加载。对照 5.1.1②"渐进披露控制上下文成本"。

**细节放在 references/ 还是 scripts/？**
模板类内容（需求记录模板、提问维度清单）在 references/；可执行校验（如"需求记录是否覆盖了全部回答"的检查）在 scripts/。这与 5.1.1③"能写成检查清单或脚本的，不要写成形容词"一致。

**我的发现（200 字左右）**：
这个技能包让我第一次看清"技能"和"提示词"的分界：提示词是一次性的，技能是把"提问—记录—沉淀"这套流程固化成跨会话复用的资产。触发描述决定它会不会被用到，渐进披露决定它贵不贵，可执行脚本决定它稳不稳定。第 3 周我们只用 Superpowers 工作流重做 v2 时，我会先按它的触发描述组织任务描述，让工作流被正确触发；同时学习把本项目的领域规则（协同归属 R1/R2/R3）沉淀成 references 式清单，而不是在对话里反复交代。
